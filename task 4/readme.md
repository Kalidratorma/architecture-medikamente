# Task4 — Диаграмма Исикавы

Файл диаграммы: `ishikawa.drawio`

## Категории причин и ключевые проблемы
- **Инфраструктура:** единый физический сервер (SPOF), 1С в файловом режиме, перегруженная офисная сеть, нет резервирования, отсутствуют среды dev/stage.  
- **ПО / Архитектура:** монолит/общие ресурсы, интеграции по файлам, нет API‑контрактов и gateway/WAF, нет очередей/шины событий, отсутствует SSO/RBAC/ABAC.  
- **Данные и интеграции:** Excel/JPG/PDF на общем диске без аудита, нет шифрования at rest/in transit, нет тегирования/линейки (Data Catalog), лаборатория без HL7/FHIR API, платежи без токенизации.  
- **Процессы:** ручные операции и дубли, нет плана миграции/отката, нет CI/CD и тестов, релизы нерегламентированы, нет SLA/SLO.  
- **Персонал / Организация:** низкая зрелость DevSecOps, нехватка экспертизы (K8s/DB/Sec), зависимость от ключевых людей, обучению ПДн уделяется мало внимания.  
- **Безопасность / Регуляторика:** несоответствие ФЗ‑152/ГОСТ, GDPR/HIPAA, нет DLP/маскирования, отсутствует KMS, нет аудита/IR‑процедур, не проработана модель угроз.  
- **Операции / Наблюдаемость:** нет централизованных логов/метрик/трейсов, отсутствует алертинг по ПДн, бэкапы не проверяются, нет DR/BCP, нет нагрузочного тестирования.  
- **Миграция / План:** параллельный учёт при переходе, не определён cut‑over, несовместимость форматов, риски перфоманса при росте ×5, нет подтверждения пилотами.

Эти проблемы отражают текущее состояние и цели компании «Медикаменте», описанные в методичке спринта и требованиях к заданиям 1–3.

## Рекомендации
1. **Уничтожить SPOF, подготовить среды:** кластер/облако, HA для сети/питания; ввести dev/stage/prod.  
2. **Ввести API‑контракты и шлюз:** Kong/Apigee + WAF/Rate Limit; заменить интеграции по файлам на REST/gRPC + очереди (Kafka/RabbitMQ).  
3. **Безопасность данных:** шифрование TDE/SSE‑KMS, TLS/mTLS, токенизация платежей (PCI DSS), KMS/Vault, аудит доступа.  
4. **Data Governance:** Data Catalog (теги/линейка), NiFi на потоках ПДн (маскирование/DLP), ролевой/атрибутный доступ (Keycloak+AD).  
5. **Процессы и DevSecOps:** CI/CD, автотесты, регламенты миграции/отката, SLA/SLO, change management.  
6. **Наблюдаемость и DR:** централизованные логи/метрики/трейсы, алертинг по ПДн, регулярные бэкап‑дрили, планы DR/BCP.  
7. **Пилоты и поэтапная миграция:** MVP, обратная совместимость адаптерами, миграция данных партиями, cut‑over с ограниченным окном.
