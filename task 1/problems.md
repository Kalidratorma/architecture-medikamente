# Проблемы — Работа с данными (As-Is)

## 1. Хранение и управление данными
- Разрозненные данные: пациенты, записи, платежи, ТМЦ хранятся в Excel, 1С и PDF без единой системы.
- Отсутствие централизованной БД → дублирование, ошибки, сложность поиска.
- Неструктурированные сканы (PDF/JPG) без тегирования, lineage и политик хранения.
- Нет политики хранения данных (retention) — как долго хранить сканы, логи, историю.

## 2. Безопасность и контроль доступа
- Нет ролевой модели (RBAC/ABAC), файлы доступны всем на общем диске.
- Нет шифрования персональных данных при хранении и передаче (ФИО, диагнозы, платежи).
- Нет аудита (кто и когда изменял данные).
- Уязвимость к внутренним угрозам (копирование/удаление файлов сотрудниками).
- Уведомления (звонки/email) не минимизируют ПДн.

## 3. Процессы и автоматизация
- Ручная запись пациентов в Excel, возможны накладки и ошибки.
- Двойной учёт платежей (Excel + 1С).
- Нет интеграции между Excel и 1С → ручная синхронизация.
- Нет онлайн-записи (MVP только в планах).
- Нет валидации вводимых данных (телефон, email, идентификаторы).

## 4. Инфраструктура и масштабируемость
- Один физический сервер (Windows Server) → риск отказа.
- Нет резервного копирования, кластеризации, репликации БД.
- Нет облачных решений — сложно масштабировать при открытии филиалов.
- Устаревшие файловые режимы 1С.

## 5. Аналитика и отчётность
- Ручные отчёты в Excel.
- Нет BI/дашбордов → руководство не видит KPI в реальном времени.
- Нет автоматизации аналитики и прогнозирования (ML/AI).

## 6. Интеграции и API
- Интеграция с лабораторией небезопасна: риск IDOR, требуется контракт-first API.
- Нет унифицированных API для внешних сервисов.

## 7. Соответствие регуляторным требованиям
- Несоответствие GDPR/HIPAA и ФЗ-152: данные не защищены должным образом.
- Нет политики минимизации данных (Privacy by Design).
- Нет 2FA для кассиров, PCI DSS для платежей.
- Риск штрафов и потери репутации.
